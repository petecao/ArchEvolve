## Why a worker-context projection is compatible

Spec D06 requires applicable strategies in the profile-package handoff. The full immutable package remains unchanged and retrievable. D07 requires its exact source/package identity and constraints, which remain unchanged. D08 says the worker applies the submitted strategy; it does not choose another optimization. No clause requires every alternative catalog match to be duplicated inside the internal worker prompt after the producer has selected its intent.

The existing 523066-byte context2 prompt includes 264213 bytes of `profile_package.strategies`: 130 catalog matches (34 loop_tiling; 24 each packing, simd_gather, software_prefetch and vertex_reordering). None names the submitted `upstream-hybrid-dx100-top-down-offload` strategy. These are alternatives, not the submitted annotations, operation requirements or protected source. The original source_files, annotated payload, full read-only API headers, explicit target explanation, exact slot declarations, dynamic-memory data, timing context, source/build references and protections must stay.

The local implementation adds an explicit opt-in `parameters.prompt_projection: omit_unselected_strategy_catalog.v1`. Default rendering remains byte-identical. For opt-in, it verifies the full sealed package (or explicitly labeled legacy contract fixture), keeps all matching submitted-strategy rows, and omits only rows naming other strategies. An ambiguous catalog identity is rejected instead of silently omitted. The worker sees a labeled partial `profile_package_context`, not a purported replacement sealed record. The projection manifest preserves the full package ID, identity hash and canonical record hash; each omitted row retains its original index, strategy and canonical row hash. Every other package field is preserved exactly. The store still retains and returns the full package.

The actual retained prompt rendered through both the unchanged 07ba renderer and the new default renderer is exactly 523066 bytes, SHA 3a42edd717c1ea13bdd28a935459cb0209709375d077b06504ff0f623ae5e992. Opt-in rendering of that same request, changing only the explicit option, produces 275533 bytes: 247533 fewer bytes, including the projection manifest. This is a local renderer experiment, not a new finalized submission payload. It does not prove that the next provider call will finish or produce a correct candidate.
