# Fact Discipline

Copied 2026-09-22 from the owner's MemAcc rules.

1. **Show the code, not just a description.**
   When you explain an implementation, show the actual code that implements it —
   the real file and lines. If the code does not yet exist (a proposed design, a
   general concept, or code outside this repo), say so plainly instead of citing
   something that isn't there.

2. **Show the evidence, not just the claim.**
   When you assert a result — a speedup, a fix, a passing test — back it with the
   command and its output, not the assertion alone.

3. **Show the recipe, not just the number.**
   When you run a benchmark or measurement, record the command, parameter
   settings, and environment so the result can be reproduced.

4. **Absence claims require a code search.**
   Never say a feature, flag, or check does not exist without showing the
   search command and its empty output against the primary artifact.
