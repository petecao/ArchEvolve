## Storage, binding and destruction

initializer, immediately before its QueueBuffer. The exact pointer-to-array type
`swdb_private_NodeID_array *` represents 16384 live typed elements. Constructor
and binder receive this private object explicitly. A source-backed default-size
qualification replaces the constructor's former generic size range with
`given_size == 16384`; this is already true at the real source call, not an added
desired-result premise on the TD caller. Generic constructor correspondence is
refused. No VLA support is assumed.

`swdb_bind_private_NodeID_array` has an ordinary body: it stores the address of
the typed array into the private pointer output slot. It neither reads nor
initializes payload. Its output initializedness must be proved from this store.
The constructor copies that pointer into its field through the existing private
out-slot ABI. No `calloc`, static/global twin, memset, poison, mask assertion,
builtin initialization fact or synthetic initializing havoc exists in this path.

`gapbs_buffer_domain` describes a live span through `self->local_queue` and the
exact default extent, rather than equality with a global. Existing push/flush
prefix initializedness requirements and actual store/copy postconditions remain;
inactive cells can retain initialization history. A pointer object's initialization
does not imply any pointed-to element is initialized.

The destructor is an explicit lexical destruction marker with no generic delete
or danglingness claim. Actual retirement occurs at its immediately following
caller block exit. Every admitted TD/control call site has that adjacency and
no payload use in between. Thus this is a proposed whole-scope refinement:
the source heap array is projected to the private typed object until its last
observable use, then both lifetimes end. The helper marker alone does not prove

The compiler-created object is not an extra incoming TD argument. Its creation
