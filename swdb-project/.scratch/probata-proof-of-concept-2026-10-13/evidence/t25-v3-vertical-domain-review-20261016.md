## Minimal semantic extension

1. **Typed-int embedding and load.** Heap.cell currently distinguishes Integer from Pointer; initialized_at alone does not establish either constructor or integer range. t25_repr currently asks only initialization for buffer elements. Define, without axioms, int32_value(v) = -2147483648 <= v <= 2147483647, and an initialized int-cell relation containing typed_reads(...,4,4), initialized_at and contents = Integer v with int32_value(v). A total load_int may use datatype pattern matching; its default Pointer branch must never justify a source int read. Require/prove the int-cell relation at every evaluated load. This belongs in the source-int-object embedding relation, derived from the actual source's typed initialized int cells, not a new caller requires. Do not assert globally that every initialized heap cell is Integer: pointer fields are initialized too. Existing universal fill obligations prove a stronger mathematical-value property; a source int argument supplies its own range. Preserve the existing limited typed-cell semantics and refuse partial-byte/cast/type-punning mappings rather than silently extending them.

2. **Arbitrary copy, not uniform fill.** Define copy_prefix(H0,H,b,bo,f,k) to mean that each 0 <= j < k is initialized as a typed int in f at 4*j and equals the arbitrary source value in H0 at (b,bo+4*j). H0 is the actual grow-entry heap, never a fresh unconstrained desired-value map. Keep the source live and unchanged through copying. Each source value can differ; the caller's all-7 fixture is a specialization only. A definitional load plus put_integer suffices; a generic raw-cell copy would still need its source type bridge and must not manufacture integer initialization from Pointer cells.

3. **Allocation identity and lifecycle.** Reuse dynamic allocation/release definitions only with their mapped access and output obligations. For automatic receiver creation, add a definitional begin-automatic-object transition with a fresh issued/live ID, extent24, align8, writable=true, dynamic=false, all initialization bits false, and complete prior-object frame. Generalize the uniform address-output relation by byte extent/alignment if needed. Do not model the receiver as malloc(6): that incorrectly grants freeability. An end-automatic-object transition may share release's alive-bit update but is a separate source lifetime event, with no call to swdb_free and no dynamic-freeability claim. Prove all receiver aliases invalid after that event. The ID is never reused; numeric address reuse is allowed while retaining dead issued identities.

4. **Source-local correspondence is indispensable.** Derive receiver creation from the actual automatic declaration and current target layout/WP local block, including alignment, distinct identity, initialization state, entry/exit timing and source call binding. An abstract transition or concrete empty-heap witness alone does not connect it to the caller. Address freshness/placement is a declared local-object semantic output, not a hidden n-dependent premise or a new assumption that arbitrary incoming objects are absent. Keep arbitrary incoming well-formed heaps, dead identities and raw aliases. If a placement-existence claim is needed, discharge it for finite issued IDs in the unbounded address abstraction or declare the exact source-local semantics trust boundary; do not introduce a finite address pool or unexplained automatic-allocation-success assumption.

## What may be reused and what may not

The existing 27 positive count/value packet shapes (26 global checks plus the numeric kernel), source groups C1-C9, general allocation properties, universal fill loop and constructor frame are suitable **templates** for qualified ctor_count_value. The existing feasibility/zero-size/address-reuse controls remain controls, not caller premises. Rebuild exact qualified source spans and statements, rebind changed theory/translation/checker identities and execute afresh before recording proof. New QC1/QC2 posts, typed-int embedding and L1/L2 local lifetime are not already supplied by the old public model certificate.

Existing dtor groups D1-D7 and definition-level release/frame/alias templates can be re-instantiated without narrowing standalone overlap behavior. Growth needs genuinely new G1-G9 obligations: uniform filled_prefix cannot represent arbitrary copying, constructor frame cannot allow intentional old-buffer death, and ctor's receiver-field sequence is different. Fresh reserve, data/index and caller composition are also required. An accepted constituent body proof is a dependency only after exact current admission and source binding; an independently checked source body can instead be inlined. Neither choice permits an unproved desired contract to become a hypothesis in its own proof.

## Constraints and semantic blockers before actual handoff

There is no additional legitimate ordinary caller premise beyond n>=0 for the three frozen int-n fixtures: int32 bounds derive both (size_t)n<=max and (size_t)n+1<=max. Exact constructor capacity=n, rather than just valid/size=n, is essential to derive that n+1 grows and n does not. Keep that capacity post visibly qualified and implementation-specific. Establish unary eligibility from this constructor and preserve it through reserve; do not infer exclusive ownership or general multi-vector safety. Arbitrary external aliases may be legal before free and stale afterward.

**Two unimplemented semantic bridges block an actual proof handoff:** source initialized-int values to Heap.Integer cells, and source automatic receiver creation/destruction to fresh non-dynamic heap identity/lifetime. The new copy/release/frame/caller proof obligations above must then be completed. These gaps do not invalidate an explicitly unsupported preparation checkpoint. A candidate that merely assumes typed values/receiver placement/current desired model contracts, proves a uniform-value grow, drops old-buffer frames, resets aliases, or claims that no pointer-sharing vector exists would be unsound or over-scoped.
