## B. Output-slot ABI as a source-preserving lowering

For the actual normal defined scalar/pointer return families, lower the return channel to a caller-private, properly typed live output object and a void procedure. The lowered callee explicitly stores the original returned value into that object; the caller then consumes that initialized object at the original expression result point. This is a change to the **hand translation interface**, not to the real C++ algorithm. It must be a new reviewed source/method freeze with a semantic mapping; no old result is readmitted.

Apply the rule uniformly to the15 returning helper bodies and5 returning standard/builtin model interfaces, including the currently unused atomic-load declaration. The4 already-void helper bodies and delete summary remain void. Do not rewrite only the two failing calls and silently preserve a different return model elsewhere. Every TD/device call interface that crosses this chosen lowering boundary must be inventoried, with unsupported families explicitly outside scope. The concrete compile/proof artifact still retains all19 helper bodies; additional output writes/slots/RTE checks legitimately change goal counts, so compare obligations by semantic map rather than forcing245/352 numerically.

The standard/builtin summary transformation must be justified per operation. Atomic fetch-add writes the original old scalar value to the private slot and preserves the modular size_t update and initialized target. CAS preserves the boolean result and target update rules; atomic load preserves the original scalar read. The allocator adapter writes its existing fixed-storage pointer; it does not initialize array payload. Copy preserves destination updates and returns its endpoint through a private pointer slot even when that value is unused. These remain trusted standard/builtin abstractions with the same previously declared limits, augmented only by the source-return-channel store semantics. No arbitrary result axiom is introduced.

Functional postconditions replace references to the original returned value with the value in the output object at normal return. Frames gain only that private output write; all old writes, nonwrites, numeric/boolean/pointer relations and initialization properties remain. For bodies, every returned expression becomes the same expression's store plus void return, after recursively lowering any nested calls. For summaries, the output-store relation and initialized output object must follow the source primitive's defined normal-return semantics, not the goal one hopes to prove. New-array allocation failure/exception behavior and the fixed one-live-buffer adapter scope remain explicit limits, rather than being upgraded to a general allocator theorem.

The caller must introduce the slot itself and prove its valid/aligned lifetime and separation from preexisting source objects. This is a compiler-created private object, not a stronger precondition imposed on the original caller. Preserve exact result type, including pointer versus pointed-to type, const-related value conversion and boolean range. Do not reuse one slot across overlapping nested lifetimes or let its address escape. Every source argument is evaluated once; preserve side effects and short-circuit execution. In this unit the nested pointer getters are observationally pure modulo their private slot, but that fact must be verified for each call rather than assumed for a general C++ function.

For constructor local_queue, obtain the allocation pointer in a fresh local output object, then assign the field from that initialized object. For flush copy_start, obtain the old reservation count in its fresh output object and consume it as before. Existing ordinary assignment/copy-init semantics then transfers initializedness explicitly. The added private storage must not alter master/shared/local queue ownership or aliasing, and no global/source object may be modified solely to support the lowering. This is an ABI/dataflow transformation; there are no new loop proof hints or desired-result caller premises.

Qualification must cover both directions for normal defined source execution: project the lowered state by removing fresh slots to recover original state/return/observed effects; extend original execution with fresh disjoint slots to realize the lowered one. In addition to functional equivalence, retain source initialization/RTE obligations so an uninitialized original return-expression read cannot be hidden by initializing the newly stored value. Preserve pointer lifetime/array provenance, nonescape, frame separation and source thread assumptions. The scope remains threads=1; it does not establish the original OpenMP/device semantics or C++ class binary-layout identity.

## C. A narrowly justified verifier correction

The conceptual missing operation is the initialization component of the destination store associated with a normal return assignment. A verifier correction is admissible only after establishing that actual source family's returned scalar/pointer value is defined, and that the call's destination store occurs with the appropriate alias/lvalue/frame semantics. It must initialize the destination **object**, never the referenced pointer payload or arbitrary compound padding.

Both CfgWP's call path and StmtSemantics' automaton call path contain the value-only transfer shape and need independent review. A broad rule that all call results or all assigned locations are initialized would be unsound for other memories, compound returns and retained uninitialized outputs. Volatile stores, exceptional/nonreturning paths and destination aliases require explicit scope. The existing undefined function/source-body obligations must still reject a genuinely uninitialized return-expression read. No proof exemption may be introduced at the three failing goals.

Keep any corrected verifier in a distinct, pinned method/runtime artifact; never edit the installed frozen toolchain and call it official33.0. Review meaningful semantic controls before admission: initialized scalar/pointer return transfer, a returned pointer to uninitialized payload that still fails payload-read initialization, an invalid source return read that still fails RTE, private-slot alias/lifetime violations, and compound padding exclusion. These are proposed future correctness checks, not tests executed here. This option changes the trusted verifier, so output-slot lowering is preferable when its restricted source equivalence is simpler to audit.

## Offset: preserve the real C representability domain without abstract byte scaling

Let first and last denote ordered elements (or allowed one-past endpoints) of **one actual live, correctly aligned contiguous NodeID array object**, with subscripts i and j and symbolic span n=j-i. Physical byte offset difference is sizeof(NodeID)*n. With positive sizeof(NodeID), the existing mathematical byte bound is equivalent to n<=PTRDIFF_MAX. The source uses integer arithmetic in this guard, so no machine multiplication overflow is introduced in the specification. This derivation is a statement about actual array representation; it is **not** an in-model axiom equating WP's abstract table_to_offset with byte scaling. [N3337 additive operators,5.7 paragraphs5–6](https://timsong-cpp.github.io/cppwp/n3337/expr.add) specify the same-array and representable pointer-difference conditions.

Same allocation/base, liveness and alignment alone do not prove this array identity: separate objects or subobjects in one arena can share a base without legal array subtraction. The eligible source producers are typed new-array/static-array objects with preserved element provenance; arbitrary incoming graph pointers and in-place storage reinterpretation need separate justification. Zero span can use equal live allowed endpoints without dereference; an expired/null/zero-allocation pointer does not gain legitimacy from a zero length. Keep the original frozen object's liveness restrictions.

A sound prospective domain translation represents the span by an existing source-backed bounded element count and endpoint relation **before using pointer subtraction**. It must retain live endpoint formation, same actual array, order, readable/initialized source cells, writable destination cells, nonoverlap and all old lifetime/frame rules. The caller's witness is its existing symbolic in count with in<=local_size<=16384, not a new assumption that the failing copy precondition holds. More general callers must establish their own actual array span and representability; the whole allocation need not be smaller than PTRDIFF_MAX if the particular span fits.

The logical typed difference is supported directly by LogicSemantics418/CodeSemantics229→MemTyped.loc_diff1033–1037, which divides the internal cell difference by object length. This avoids the unbounded physical table_to_offset conversion when expressing the same source span. Domain replacement would need a recorded external source-equivalence proof under the exact array-object domain and a new contract/method identity; it must not be described as proving the old abstract byte-table clause internally. If policy requires the old ACSL byte-offset clause literally unchanged, that obligation remains blocked until a properly justified memory-model conversion is supplied.

Do not insert a scaling axiom, assume the old bound at the call site, or use a potentially undefined subtraction to establish its own representability. Do not simply select Bytes as a presumed fix: the pinned MemBytes916–919 also delegates base_offset to the same table conversion, although its pointer-difference arithmetic uses byte size. Any alternative representation needs actual semantic qualification, not a model-name inference.
