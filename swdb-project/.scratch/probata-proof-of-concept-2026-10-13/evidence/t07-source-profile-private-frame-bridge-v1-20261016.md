## One-thread profile

The counted launch must preserve OMP_THREAD_LIMIT=1, OMP_NUM_THREADS=1 and
OMP_DYNAMIC=FALSE from process start. Reject unknown replacement/preload or
runtime selector contexts rather than inheriting them. Bind the exact selected
compiler, source/macro/include closure, OpenMP library and profile receipt.
The selected23source files have no spelling of an OpenMP ICV setter or
num_threads override; this is an exact finite source trace, not a generic
whole-linked-program callgraph proof. Standard compiler/library execution and
absence of hidden nonstandard ICV changes belong explicitly to the TCB.

OMP_THREAD_LIMIT bounds the contention group, OMP_NUM_THREADS supplies the team
request and disabling dynamic teams prevents runtime adjustment. The standard
thread number belongs to the current team and is zero for its sole thread.
These are accepted OpenMP semantics, not new logical assumptions designed to
make a TD postcondition true. Sources: [thread limit](https://www.openmp.org/spec-html/5.1/openmpse67.html),
[team request](https://www.openmp.org/spec-html/5.1/openmpse59.html),
[dynamic teams](https://www.openmp.org/spec-html/5.1/openmpse60.html),
[thread number](https://www.openmp.org/spec-html/5.1/openmpsu123.html).

A bounded native observer compiles once with the exact selected Clang/libomp
and records team cardinality and thread IDs inside a real parallel region. It
runs the positive one-thread profile and a safe deliberately wrong two-thread
profile. A public consumer accepts only the exact positive environment,
inside-region cardinality/IDs, type widths and dladdr-resolved pinned libomp.
The wrong profile must refuse. Its sequential outside count is retained only
to demonstrate that an outside count of one cannot establish the active team.
[OpenMP defines the sequential result separately](https://www.openmp.org/spec-html/5.1/openmpsu121.html).

This observer is installation/profile evidence. It does not execute or
instrument the original TDStep, does not claim observation of that exact team,
and is never a TD proof. Source gate013's existing exact one-parallel-body AST
plus this enforced profile and the declared OpenMP TCB supply the scoped

## Minimal private frame rule

Use the standard typed-object/lifetime semantics as compiler TCB. Normal
successful source new int[16384] creates an actual typed array with suitable
alignment and an initial-element pointer; absence of a payload initializer
leaves the scalar payload uninitialized. The model's ordinary automatic
NodeID[16384] supplies a typed same-extent private object during its lexical
lifetime. This is a source-qualified private-storage replacement for the one
selected site, not a generic allocator ABI or a layout claim about C++ objects.
[WG21 new-expression rules](https://eel.is/c++draft/expr.new) and
[initialization rules](https://eel.is/c++draft/dcl.init) describe the standard
mechanism; the exact compiler selection remains C++11. The current draft is
cited for that unchanged mechanism, not for later language additions.
For the C model, [N1570 sections6.2.4 and6.7.9](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)
give automatic lifetime and absence of automatic initialization.
