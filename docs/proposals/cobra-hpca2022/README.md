# COBRA HPCA 2022 proposal for Eric

Propose **one required `write / tuple_bin` mapping** for base COBRA. Hardware collects supplied index/value pairs and repartitions them into per-thread memory bins; CPU software later performs Accumulate. [Proposed addition](proposed-addition.json) contains located claims, obligations, reference parameters and one operation. This is a reviewable proposal, **not production admission**. ## Exact required interface

Use the published Neighbor-Populate PB mapping (pp. 3–4, Algorithms 1–2) to make the responsibility boundary concrete. The original kernel writes `neighs[offsets[e.src]]` and atomically increments its offset. PB Binning instead collects `(e.src, e.dst)` per thread. Software Accumulate partitions by bin, traverses each thread's tuples, reads the source offset, writes the neighbor, then performs ordinary Add on that offset. Disjoint bin ownership removes that example's atomic requirement; hardware binning does not execute either destination write or increment. Neighbor order may vary because the application accepts unordered neighbor lists. This legality argument must be established afresh for another application.

No instruction encoding, C prototype or universal legal ranges established. |
| Unnamed offset initializer, p. 8 §V.E/Fig. 9 | Buffer ID and starting bin offset initialize LLC C-Buffer tags. Software precomputes per-thread bin counts and offsets. | Bin-base setup, register binding and offset byte scaling are unspecified. Do not invent a fourth named API. |
| `binupdate`, pp. 6–7 §V.B–C | Supplied index/value pair selects L1 C-Buffer by range and appends at its tuple counter. Full counter wraps and triggers eviction. | Required tuple collection; no direct application destination access or old destination value. |
| `binflush`, p. 8 §V.E | Serial per-core scan of nonempty L1, L2, then local LLC buffers, draining partial lines to memory bins. | Paper requires all tuples in bins before Accumulate. No complete observer-visible done/ack/fence protocol is specified. |

A paper-backed conceptual sequence is: configure each level; provision private bins from precomputed counts and initialize LLC offsets; issue `binupdate(e.src,e.dst)` for each edge; invoke residual flush; establish a safe all-producer/drain/visibility boundary; then run Algorithm 2's software Accumulate. The release boundary is an implementation obligation, not an invented instruction. This description is not executable code or an ABI.

## Collection, issue and policy

C-Buffers occupy cachelines outside the shared-memory address space and are not byte addressable (pp. 6–7). High index bits identify the buffer and its reserved set/way; low bits identify the bin range. Counter-selected append slots retain the full pair and its multiplicity. The word “coalescing” describes tuple packing in base COBRA: it does not mean same-index arithmetic reduction.

Each level has its own range, with fewer coarse L1 buffers and more fine LLC buffers (p. 5/Fig. 6). On a full buffer, a cacheline enters a FIFO eviction buffer. A binning engine extracts tuples sequentially and serially inserts each into the next level's selected C-Buffer (p. 7/Fig. 8). Repartitioning can change global traversal order. No stable global sort, cross-core ordering, general scatter schedule, cross-level arbitration or starvation guarantee is claimed.

LLC buffers belong to the core's assigned NUCA bank(s). A full LLC line writes to the thread's bin at `BinBasePtr + BinOffset[binID]`; tag-stored offsets advance by the number of emitted tuples and tuple counters reset (pp. 7–8/Fig. 9). Precomputed counts reserve memory-bin space. Cache-way reservation prevents displacement by the current process's other data; it is distinct from proving downstream eviction credits or reserving every outstanding write. Queue-full backpressure and flush progress need a concrete implementation binding.

The Sniper model retires `binupdate` only at the ROB head, like a store. Operand-selected L1 buffers avoid the ordinary address-generation port (p. 9/§VI). Retirement says nothing about downstream drain or consumer-visible bin writes. `binflush` walks levels in order and supports partial lines, but the inspected text does not explain exactly how it waits for pending FIFO contents and outstanding memory writes, joins cores, reports completion, or supplies a consumer fence. No global write-completion guarantee follows from its name.

## Bottleneck and reference settings

Software PB faces a tradeoff: many bins improve Accumulate locality, but their software C-Buffers exceed small-cache capacity and incur management instructions and branches (pp. 4–5/Figs. 4–6). COBRA uses the small L1 buffer set for cheap insertion while progressively repartitioning toward many memory bins. Eviction bursts can still stall a full FIFO; reserving too much L2 capacity can harm streamed/prefetched data. Initialization, bin traffic and CPU Accumulate remain costs. There is no measured DX100 benefit in this proposal.

Table II (p. 9) reports 16 OoO cores at 2.66 GHz, 4-wide issue, 128-entry ROB, 48 load / 32 store queue entries; 32 KB 8-way L1, 256 KB 8-way L2, and 2 MB/core 16-way LLC. Load-to-use timings are 3/8/21 cycles (local LLC bank); DRAM latency is 80 ns. The default reservation is all but one L1/LLC way (7/15 in that hierarchy), and one L2 way with a stream prefetcher (p. 6 and p. 11). These are reference settings, not general allowed ranges.

The p. 7 example packs eight 8 B tuples (4 B index + 4 B value) in a 64 B line using a 3-bit counter; this does not specify numeric type support. §VI reports 4 B tuples for Degree-Counting/Integer Sort, 8 B for Neighbor-Populate/Pagerank, and 16 B for the remaining evaluated workloads. Only the 8 B Neighbor-Populate mapping is proposed here. Little's Law estimates 14 L1→L2 and one L2→LLC eviction-buffer entries; the burst-aware DES analysis motivates 32 L1→L2 entries (p. 7 and p. 11/Fig. 13a). The single-entry estimate is explicitly labeled an estimate. Namespace size, ranges and offsets remain workload/configuration dependent.

## OS, legality and implementation limits

The no-translation path assumes system support for matching VA and PA for important structures such as bins (p. 8). `mlock` is mentioned to avoid swapping critical pages; locking alone does not establish VA=PA. Per-process partitioning pins buffers during Binning, but another process on preemption can evict partial lines. The paper discusses those transfers and modeled bandwidth waste, not an inspected OS implementation, migration protocol, save/restore layout or fault retry. Tag/coherence metadata reuse relies on private C-Buffers and cannot be extended to arbitrary coherent data lines.

Application reorder legality, aliasing, bin allocation bounds, offset overflow, tuple lifetime, numeric order and CPU Accumulate synchronization remain obligations. Even mathematically commutative floating-point addition need not preserve bitwise results. Base COBRA preserves tuples rather than combining their values. The separately discussed **COBRA-COMM** uses LLC reduction and shared buffers (§VII.C, pp. 11–12); none of those atomic/reduction capabilities belongs to this mapping.

## Representation decision and validation

[Admission decision](admission-decision.md) explains why tuple materialization fits a narrowly named v0 write mapping. The operation carries textual result, ordering and completion semantics; empty address patterns/types remain unknown. It cannot satisfy gather, generic scatter, RMW, reduction or old-value queries. An unconstrained `write` query can return it as a `mapping_reference`, with the binning scope and undischarged requirements; this is a deliberate consequence of v0, not permission for destination writes.
