The DX100 records now describe how required indirect loads retain original element identity while changing memory request order. Josh's candidate comparison can inspect admission, grouping, request selection, downstream blockage and result placement without inferring them from a `gather` capability. The integration uses the existing `internal_mechanisms`, `claims` and `sources` fields in [hardware-v0.1.yaml](../catalog/hardware-v0.1.yaml). ## Mechanism and resource lifetimes

| Stage | ISCA2025 author edition (`dx100-paper-v2`) | Public model (`dx100-artifact-e4fc4af`), required ILD |
|---|---|---|
| Admit | Tile size/ready bits coordinate host access; element finish bits allow pipelined producers (§3.5 p.6). | IF rejects full instruction storage, destination conflicts and specified same-range hazards within `maa_id`. Ready scan starts at a random offset; Fill still waits for each condition/index element, in original iteration order (IF.cc 185–300; IndirectAccess.cc 399–528). |
| Translate/group | Physical CH/RA/BG/BA select slices; row and column entries group accesses (§3.2 pp.4–5). Fig.4 depicts 64 row slots and up to 8 column slots per row. | `base + word_size * uint32_index`, declared virtual bounds, aligned translation, then configured Ramulator2 mapping determine slice/grow and physical line. Same-row line overflow may use another row record. Capacity failure retains the failed iteration (MAA.cc 261–334; IndirectAccess.cc 113–241, 460–528; Tables.cc 253–281, 347–399). |
| Associate duplicates | Tile-sized Word Table retains word offset and backward `Previous i` links with a column tail (§3.2, Fig.4). | OffsetTable retains `(itr,wid,next_itr)` and line first/last pointers. Matching unsent line appends a consumer without another line slot. Duplicate words remain multiple consumers (Tables.hh 44–169; Tables.cc 142–194, 253–281). |
| Select requests | Sequential scans and predetermined channel/bank-group interleave; row completion or capacity initiates Request (§3.2 p.5). | With reorder enabled, final Fill or insertion failure enters Build; producer wait alone does not. Repeated passes emit at most one line per active slice, channel fastest, then rank, bank group, bank. Within a slice, scan line slots and other records of the same grow before another grow (IndirectAccess.cc 188–210, 621–724; Tables.cc 433–470). |
| Route/block | First column insertion queries cache status and stores H during Fill; H selects LLC or memory (§3.2 p.5, §3.6 pp.6–7). | Port snoops at new packet creation unless forced. Tick-eligible per-channel/bus queues send writes before reads. Failed sends retain work and block until retry/capacity release; cache indirect classes precede stream classes. Compatible reads across units can share one outstanding packet, separately from within-unit word fanout (Port.cc 31–178, 180–279, 301–581; MAA.hh 655–695; CacheSidePort.cc 84–133; MemSidePort.cc 80–92). |
| Place response | Returned address identifies column word list; offsets select words for original `TD[i]` (§3.2 p.5). | Decode physical response line to slice/grow, consume associations, sort them by `itr`, and write every `word[wid]` into `TD[itr]`, including duplicates. This is within-response association ordering, not outgoing address sorting or a global response order (IndirectAccess.cc 868–927; Tables.cc 170–194, 313–336, 472–498). |
| Reuse/complete | Host tile readiness is specified; precise table reuse and row-complete detection are not fully specified here. | Consumed offsets/line slots become invalid. A row record is reset only after all its lines return; sent records cannot absorb additions. Request can fill released space, but batch transition waits for queued packets sent and received count equal to expected. Final Fill status is re-evaluated. Finish checks source readiness, modeled scratchpad/table latency and empty histories/tables, then publishes destination Finished/Ready and dependent-source status (IndirectAccess.cc 330–398, 725–809, 1158–1173; Tables.cc 170–217, 330–336, 472–495; MAA.cc 605–621; IF.cc 303–336). |

The added claims use `dx-internal-p2` through `p5`, `p7`, `p8` for the author edition and `dx-internal-c1`, `c3` through `c13` for the public model. Every described annotation references only its own edition's evidence. The paper's completion checklist remains unknown where these locators do not specify the model's exact state lifetime.

Default public choices are 16384 tile elements, 64 row records per slice, 8 line slots per subslice-row, 32 initial slices and one modeled cycle of row-table latency (MAA.py 13–39). Merged-bank organizations couple record totals and line slots; these numbers are not independent chosen workload parameters. Reorder is enabled by default; optional base-address/observed-row-count reconfiguration is disabled (IndirectAccess.cc 113–186, 243–329). It is separate from the fixed slice-cycle policy and does not establish adaptive DRAM open-row intelligence or correct LRU replacement.

## Existing outputs and comparison use

The existing pipeline includes these descriptions and claim/source closure in candidate YAML, comparison YAML, human comparison Markdown, handoff evidence and mechanism Mermaid annotations. Catalog snapshots preserve the entire record. No physical connections or concrete intrinsic signatures are generated from these annotations.

For Josh, the useful distinction is the lifetime of each item: a visible index element may still wait for admission; an admitted line may wait for generation or transport; an accepted request may still await its response; a placed word does not free every line in its row record or discharge host synchronization. Compare producer readiness, unique physical lines, duplicate-consumer count, slice skew, drains and transport limits under the actual legal workload mapping. Those observations would be model inputs; no benefit or speedup is asserted here.

## Remaining gaps

- Paper row-complete detection and exact table reuse timing; hardware implementation/timing of BCAM/SRAM, C++ containers and response sorting.
- Fairness, starvation freedom and downstream DRAM command ordering under competing traffic. Fixed generator cycling is insufficient evidence for these.
- Workload-specific writers, aliases, producer/consumer boundaries, legal reorderability and host synchronization. Existing requirements remain obligations; local completion does not prove global coherence or fence semantics.
- Arbitrarily asynchronous translation and fault recovery: the public local callback asserts immediate completion and panics on faults (IndirectAccess.cc 1176–1190).
- Masked `setFakeData` value/validity semantics; optional reconfiguration cache edge cases, zero-grow sentinel and Request fill-flag handling. No code fixes or executable reuse are claimed.
- Publisher-edition equivalence, paper-evaluation binding to the November public model, private/current virtualization, and matched correctness/performance measurements.

Focused regression coverage checks edition separation, unchanged typed queries, exact evidence retention and existing comparison/handoff rendering, including explicit absence of inferred wiring or speedup. The original unknown-mechanism regression uses an annotation-free fixture so absence still stays unknown.
