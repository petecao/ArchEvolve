## Required output and legality

`write / tuple_bin / execute`, with `record_kind: mapping`, honestly describes the required bin output of the transformed PB program. `binupdate` appends the supplied complete index/value tuple; LLC drain writes tuples into allocated per-thread memory bins. The proposal's result explicitly excludes destination-array updates. Hardware does not perform the later irregular store, offset increment, atomic update, reduction or old-value return. Calling this optional prefetch would misstate the required tuple output. The custom subtype describes a concrete source-scoped write form without introducing a new operation or DSL.

In §III.A–B, Fig. 3 and Algorithms 1–2 (pp. 3–4), Neighbor-Populate collects `(e.src,e.dst)` per thread during Binning. CPU Accumulate assigns bins to workers, visits the threads' bins, reads the offset, writes the neighbor and increments that offset with ordinary Add. Disjoint bin ownership replaces that example's AtomicAdd. Its legality rests on neighbor lists permitting arbitrary order. Removing duplicate tuples, combining increments, pairing an index with a different value or dropping multiplicity would skip or corrupt neighbor entries. The full pair and each occurrence must survive.

This example does not grant arbitrary reorder legality. The proposal explicitly states the absence of original global order or stable sorting. Floating-point reproducibility, integer overflow, aliasing, lifetime and application equivalence remain workload obligations. These do not follow from ordinary cache behavior or mathematical commutativity.

Private cache-way reservation establishes space/location for C-Buffers, not credits for every downstream eviction or outstanding memory write. The paper's default all-but-one L1/LLC ways and one L2 way with stream prefetching are reference settings, not legal ranges or a selected target configuration. Metadata reuse is justified by private C-Buffers and cannot establish coherent destination-array semantics.

The retained consumer-release requirement must bind stopped producers, all intermediate buffers/queues, outstanding bin writes and consumer visibility before CPU Accumulate. It remains unresolved. §V.E (p. 8) additionally assumes matching VA/PA for important structures; `mlock` only prevents swapping. Process preemption can evict partial C-Buffers. No verified kernel support, migration/save/restore or translation-fault protocol follows. These requirements cannot be inferred from ordinary caches.

Base COBRA preserves tuples. **COBRA-COMM** (§VII.C, pp. 11–12) separately adds LLC same-index reduction and an atomic LLC reduction unit enabling shared LLC buffers. Its capabilities, and the separately evaluated non-partitioned variant, are excluded from this mapping.
