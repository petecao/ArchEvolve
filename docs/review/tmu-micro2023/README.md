Schema fit is adequate for reference admission. The exact subtype, `record_kind=mapping`, `mapping_role` and prose contracts preserve the richer event supply semantics. Concrete payload and index widths lack evidence and return `needs_evidence`; an untyped exact query returns `mapping_reference`. An omitted-subtype read query can enumerate the mapping, but returns its full exact subtype and requirements. Enumeration is not gather compatibility.

Normal selection generates generic gather/stream requests (`archevolve/evidence_select.py:24`), so it cannot infer this callback grammar. Even a focused TMU selection produces only the CPU comparison for the existing BFS fixture. Explicit comparison of TMU against those requests preserves its interface and requirements and reports no matches. This is an intentional capability boundary, not evidence that an adapter exists.

For a separately supplied synthetic exact mapping intent, candidate generation (`archevolve/evidence_select.py:135`), intrinsic draft/package projection (`archevolve/intrinsic_handoff.py:19`, :182) and comparison (`archevolve/comparison.py:14`) preserve the exact result/event description, CPU contract, requirements, source closure and unknowns. Mapping is never promoted to a conditional read executor. The fixture borrows BFS request metadata only to exercise projection; it asserts no BFS-to-SpMV mapping. The v0 schema has no machine-readable callback grammar or chunk state machine; future runtime/adapter work must establish them explicitly. Ordinary generation retains the prose, rather than reconstructing it from a gather label.
