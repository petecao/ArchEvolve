# BFS acceptance coverage query

Date: 2026-09-25

`bfs-coverage REQUEST` reads authoritative records and rebuilds the derived query
index when needed. Its version 1.0 request names an `id`, the current
`candidate_protocols`, `artifact_reference_comparisons`, and
`controlled_reference_comparisons`. These lists identify the intended current
assessment; the query does not silently select a convenient older protocol.

The fixed eight cells retain the two source implementations, their assigned
instruction and supplied-code forms, and Kronecker/uniform-random families. DX100
natural-language and upstream annotated-source cells require actual acceleration;
DX100 patches and upstream structured instructions require native execution.
Every attempt remains visible, including missing candidates, failed runs,
incompatible old protocols, neutral results, and regressions.

Qualification rechecks immutable protocols, comparison inputs, exact source and
correctness bindings, real complete profile packages, ROI quantity and independent
attribution. Accelerator use requires positive modeled instruction counters and
completed unit traces for the timed execution. Full/tail and competing-parent
coverage remain independent obligations; declarations are not measurements.
Reference code cannot satisfy a generated-candidate cell or the required candidate
gain. A gain must use the corresponding unaccelerated source baseline under the
frozen profitability policy. No win over the authors' accelerated BFS is required.

The output separates retained-metadata qualification from external-artifact
verification. Available local files are rehashed. Remote unavailable files are
`remote_unverified`; missing local or changed artifacts are explicit. Neither an
unavailable file nor an absent metric is a neutral speedup. The final report cannot
claim complete acceptance while required obligations or verification are absent.

AC01–AC20 are reported individually. Criteria requiring additional contract or
handoff demonstrations remain incomplete until identified evidence exists; green
fixture tests cannot satisfy real native/simulator execution. The report supplies
evidence to the proposal owner and does not launch strategy search. Prepared SW/HW
test clients do not establish live Peter/Josh integration.
