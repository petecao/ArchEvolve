# October 1 forward-handoff plan

Scope: an offline, reviewable handoff from Peter's BFS features and Eric's catalog to Peter/Yan-Ru. Keep the current catalog and received reports unchanged.

1. Generate one candidate package with a structured draft intrinsic description, readable explanation, catalog evidence, and Mermaid interface view.
2. Accept optional, located internal-mechanism annotations in catalog designs. Preserve buffering, grouping/coalescing, reordering, issue policy, dependency tracking and completion descriptions; missing details stay unknown.
3. Accept explicit source-context bindings and related-statement groups. Bind only matching file/function/revision records, retain provenance, and separate workload grouping from hardware composition.
4. Compare catalog designs against the same requests, independently of selection budget. Separate execution from assistance, preserve exclusions, and expose missing mechanism/performance information.
5. Exercise sparse and fully connected BFS, validate draft contracts and render representative diagrams. Document the shared handoff fields and review responsibilities.

External dependencies: Eric's selected second fetcher and mechanism annotations; Peter's confirmation of source placement, concrete intrinsic spec and shared terminology; Yan-Ru's implementation. A local draft format does not imply team agreement. No simulator, LLM/API, benchmark execution, or numerical performance estimate is part of this step.

Catalog curation follow-up: new primary design entries should follow the meeting's major-conference/recent-publication policy. Existing paper/artifact references remain traceable supporting evidence. Conference eligibility and internal mechanisms must be reviewed with Eric; this change does not silently remove records or treat an artifact as a qualifying publication.
